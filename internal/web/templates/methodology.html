Method {{.Methodology}}

Measurements that can be challenged.

StratumStats publishes observed dimensions separately. It does not collapse subjective weights into a composite score or declare one universally best pool.

Published measurements

Availability

Conservative 95% Wilson lower bound of full-template arrivals over eligible blocks. Disappearing during an observed block counts as a miss.

Median delivery

Median full-template delay relative to the earliest structurally valid template observed for the same block and vantage.

Tail delivery

95th-percentile relative delay, exposing intermittent stalls that a median can hide.

Transport security

Whether a configured TLS endpoint successfully completed a measured Stratum session.

Protocol response timings

Connection setup is recorded as separate JSONL evidence: TCP connect (including name resolution), TLS handshake when used, mining.subscribe, and mining.authorize. Durations run from the local request start through the matching response and are aggregated independently from block-delivery latency.

mining.ping is an optional Stratum V1 extension. A valid pong is timed and may be sampled again during a long session. Unsupported responses and timeouts remain visible, but they do not reduce availability or count as failed block delivery.

Why empty-first is not scored

After a new block, Bitcoin Core validates the block, updates chain and mempool state, and assembles a transaction-bearing template. Sending coinbase-only work immediately can prevent miners from wasting time on the stale parent. Empty-first frequency is not inherently bad; only empty-to-full duration and resulting fee opportunity cost are meaningful.

Coinbase output observations

For every structurally valid job, the probe reconstructs the coinbase with its negotiated extranonces and checks whether an output matches the generated worker address script. The separate Coinbase observations page reports only present, absent, varied, or no-data results with sample counts. Absence alone does not establish whether a pool will pay correctly by another mechanism.

When the worker output is present, the observed pool fee is 100 × (all coinbase outputs − worker outputs) / all coinbase outputs. Optional donations or configured splits can be included, so this is the effective percentage visible in that job—not a claim about advertised policy. No fee is inferred from jobs where the worker output is absent.

What is deliberately excluded

Pool size, popularity, advertising, sponsorship, subjective reputation, unverified operator claims, and any composite score. Payment correctness outside the observed coinbase outputs still needs a controlled hashrate/payment study.

Anonymity and its limit

Each connection uses a newly generated valid-looking Bitcoin address, ordinary worker name, and rotated miner agent. Credentials are never persisted. This reduces special treatment based on a known benchmark account, but it does not conceal the probe’s source IP. Published vantage labels should be coarse regions, never hostnames or IP addresses.
